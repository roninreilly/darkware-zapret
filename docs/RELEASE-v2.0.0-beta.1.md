# Darkware Zapret 2.0.0-beta.1

**Предварительный релиз.** Стабильной версией остаётся 1.0.39. Новая архитектура для macOS: локальные SOCKS-движки для совместимых приложений и отдельный экспериментальный пакетный режим на основе Flowseal Mac. **Версия Darkware 2.0 не означает интеграцию zapret2**: upstream zapret2 пока не поддерживает macOS.

## Изменения

- Пакетный backend `nfqws`/`utun`/BPF на основе Flowseal `zapret-mac-discord-youtube` 1.1.2, с 21 исходным профилем; требуется macOS 14+.
- `tpws` и ByeDPI в локальном SOCKS-режиме на macOS 13+. Для запуска самих SOCKS-движков системная служба и root не требуются.
- Системный SOCKS включается явно; прежние настройки сети сохраняются для восстановления.
- Отказ от старой модели с доступным для записи root-конфигом и sudoers-скриптами; предусмотрена миграция установки 1.x.
- Диагностика через отдельные аргументы процесса, проверка домена и различение прямого соединения и SOCKS. Проверка HTTPS не выдаётся за проверку голоса Discord.
- Исправлен несовместимый с macOS tpws-пресет: `--oob` больше не комбинируется с Linux-only `--disorder`; сохранена миграция старого `Fake Packets`.
- Сборка всех движков из закреплённых исходников, universal-пакет, сведения о зависимостях и контрольные суммы.

## Обновление с 1.x

Остановите старый экземпляр, замените приложение в Applications и запустите 2.0. При обнаружении прежней привилегированной установки выполните предложенную в приложении миграцию с подтверждением macOS. Затем выберите SOCKS-движок или экспериментальный пакетный режим. Если прежде был настроен чужой SOCKS-прокси, проверьте настройки сети перед первым включением системного SOCKS в 2.0: 1.x не сохраняла исходное состояние.

## Ограничения

Пакетный режим экспериментальный. Требует прав администратора и может конфликтовать с VPN/TUN и другими средствами маршрутизации. Успешный запуск процесса или HTTPS-запрос не доказывает обход DPI, работу QUIC или голоса Discord. Полевые испытания на конкретном ISP обязательны для таких утверждений. Базовый пакетный путь ориентирован на IPv4; полноценная поддержка IPv6 не заявляется.

SOCKS действует только для приложений, которые его используют. Настройка системного SOCKS не направляет автоматически весь UDP macOS в прокси. DNS-блокировка, IP-блокировка и фильтрация TLS — разные причины недоступности; подбор стратегии не устраняет их все.

## Проверки и публикация

Проверено локально на macOS с Command Line Tools:

- 77 самостоятельных регрессионных проверок Swift и 125 проверок с настоящими движками: все восемь SOCKS-пресетов, готовность SOCKS5, владение процессом, занятый порт и остановка.
- 10 локальных сетевых сценариев: ByeDPI передаёт HTTPS с проверкой сертификата; tpws отвечает по SOCKS5 и сохраняет защиту от подключения к loopback.
- Все 63 сочетания 21 пакетного профиля и трёх режимов IPSet проходят разбор настоящим `utunws --dry-run`.
- Изолированные сценарии пакетного supervisor/watchdog: выход движка, SIGKILL supervisor, ошибка загрузки PF и смена default route. Проверяются очистка собственного anchor и освобождение PF token; привилегированные команды заменены тестовыми.
- Копирование списков проверено на симлинки, неверного владельца, FIFO, размер и перезапись; параметры установки проверены на инъекции.
- Приложение, три движка и вспомогательный бинарник содержат arm64 и x86_64. Deployment target приложения — macOS 13; пакетного движка — 14.
- Подписи проверены, DMG смонтирован только для чтения, ZIP распакован и проверен, хэши сверены с sealed provenance. Исходный архив содержит тесты; генерация provenance работает без `.git`.
- Интерфейс отрисован и осмотрен в светлой английской и тёмной русской теме.

Полный `swift test` запускается в Xcode CI до публикации; локальная установка CLT не содержит модулей Testing/XCTest. Системные прокси, маршруты и DNS машины разработчика при тестах не изменялись.
