# Darkware Zapret: исследование перед 2.0

Проверено 16 октября 2026 года. Исходная точка проекта: `v1.0.39`, коммит `1d9834a5716d65b6140df24dd64fec350d461bb9` от 19 июня 2026 года. Ниже отделены подтверждённые свойства исходников от гипотез об эффективности у провайдера. Исследование не заменяет испытания на сети с действующей блокировкой.

## Главные выводы

1. **zapret2 существует**, его автор — **bol-van**. Это новый пакетный движок с Lua-стратегиями; upstream прямо исключает macOS. Подменить старый `tpws` на `nfqws2` и получить работающий Mac-порт нельзя.
2. **У Flowseal действительно появился собственный Mac-репозиторий**. Это уже пакетный путь `utun` + BPF, а не прежняя обёртка над TCP-прокси. Он открывает практически полезное направление для Darkware.
3. Старый проект нельзя улучшить одним обновлением списков: приоритеты — убрать небезопасный root-конфиг, восстановить настройки прокси, исправить модель диагностики и воспроизводимо собирать все движки.
4. Для 2.0 разумны два независимых пути: обычный SOCKS для совместимых приложений и явно экспериментальный пакетный режим для macOS 14+. Успешный HTTPS-запрос не доказывает работу голоса Discord.

В публичных [issue #8](https://github.com/RoninReilly/darkware-zapret/issues/8) и [issue #2](https://github.com/RoninReilly/darkware-zapret/issues/2) есть пользовательские сообщения о потере связи/Discord. Они задают сценарии регрессии, но сами по себе не устанавливают причину и не доказывают её исправление. Проблемы transparent `tpws` на новых macOS также обсуждаются в [upstream issue #1482](https://github.com/bol-van/zapret/issues/1482); для 2.0 нельзя считать этот путь надёжным базовым режимом.

## Решение для 2.0

Сохранить совместимый SOCKS backend `tpws`/ByeDPI на macOS 13+ без root для самого процесса. Системный прокси — явная настройка пользователя с восстановлением. Добавить отдельный **экспериментальный пакетный backend** из закреплённого Flowseal 1.1.2 для macOS 14+, с 21 профилем и понятным предупреждением о конфликте VPN/маршрутов.

Не обещать «весь UDP», полноценную поддержку IPv6, универсальный Discord voice или эффективность на каждом ISP. Проверка локального запуска и HTTPS — только соответствующая проверка. Голос требует реального подключения к каналу, обмена медиапакетами в обе стороны и испытаний на блокирующей сети.

Подробная последовательность, критерии и открытые проверки: [RELEASE-PLAN.md](RELEASE-PLAN.md). Пользовательские изменения: [RELEASE-v2.0.0-beta.1.md](RELEASE-v2.0.0-beta.1.md).
