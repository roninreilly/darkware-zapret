# План обновления Darkware Zapret 2.0

Дата: 16 октября 2026 года. База: `v1.0.39`. Целевой предварительный релиз: `v2.0.0-beta.1`. Стабильная версия остаётся `v1.0.39` до прохождения полевых и аппаратных проверок. Основание решений: [исследование проекта и upstream](RESEARCH-2026-10.md).

## Цель релиза

Дать пользователю выбор между безопасным локальным SOCKS и новым экспериментальным пакетным обходом. Состояние приложения должно соответствовать состоянию процесса, настройки сети должны восстанавливаться, ошибки должны давать понятный следующий шаг. Эффективность стратегий зависит от сети и проверяется отдельно от сборки.

## Очерёдность и критерии приёмки

| Этап | Результат | Критерий готовности |
| --- | --- | --- |
| 1. Аудит и выбор архитектуры | Зафиксировать изменения после июня, реальные альтернативы и ограничения macOS. | Первичные источники с датами/версиями; zapret2 отделён от Flowseal Mac и Darkware 2.0. |
| 2. Привилегии и миграция | Удалить исполнение пользовательского `config_custom` от root и старую sudoers-интеграцию. | Миграция не вызывает старые доступные для записи скрипты; обычные SOCKS-процессы работают от пользователя; привилегированный backend принимает только проверенные параметры. |
| 3. SOCKS и восстановление сети | `tpws` и ByeDPI с явным включением системного SOCKS. | До изменения сохранён прежний host/port/enabled каждой службы; частичный сбой откатывается; Stop, выход и следующий запуск после аварии умеют восстанавливать состояние. Чужие изменения не затираются молча. |
| 4. Пакетный backend | Закреплённые `nfqws`/`utun`/BPF Flowseal 1.1.2, 21 исходный профиль. | macOS 14+; root-файлы защищены; старт/стоп/сбой чистят свои маршруты и PF-правила; обнаружение VPN и понятное сообщение; режим обозначен экспериментальным. |
| 5. Диагностика и профили | Аргументы через argv, проверка домена, сравнение direct/SOCKS, перебор совместимых стратегий. | Ввод не становится shell-кодом; HTTP/TLS-результат привязан к проверенному пути; диагностика не меняет профиль пользователя без явного выбора. Проверка HTTPS не выдаётся за проверку голоса. |
| 6. Интерфейс и документация | Выбор режима, статус, профили, настройки, объяснение ограничений; README EN/RU и заметки к релизу. | Пользователь понимает требования выбранного режима, источник ошибок и способ остановки/восстановления. |
| 7. Сборка и публикация | Все C-движки и Swift-приложение из исходников, universal DMG/ZIP, манифест и SHA-256. | Проверены обе архитектуры каждого Mach-O, содержимое bundle, лицензии, версия и минимальная ОС. Артефакты после публикации сверены с локальными хэшами. |

## Проверки до объявления стабильного пакетного режима

- Чистая установка и обновление с 1.0.39; сохранение пользовательских профилей и удаление старой небезопасной интеграции.
- macOS 13: доступны SOCKS-движки; пакетный режим корректно недоступен. macOS 14 и актуальная macOS: отдельные машины arm64 и Intel либо явное обозначение непроверенной комбинации.
- Для каждого SOCKS-движка: старт, занятый порт, авария процесса, смена профиля, Stop и выход; системный SOCKS изначально выключен, включён на чужой адрес и настроен на службе с нестандартным именем.
- Для пакетного режима: запуск, отказ авторизации, отсутствие default route, VPN, смена Wi-Fi/Ethernet, sleep/wake и обрыв процесса. После Stop остаются рабочая связь и чужие PF-правила.
- На сети с блокировкой: DNS, HTTPS Discord, Gateway WebSocket, скачивание обновлений, YouTube playback и отдельная двусторонняя проверка голосового канала Discord. Сохранить версию ОС, ISP, backend, профиль, длительность и результат без чувствительных данных.
- Сборка и исходники проходят автоматические проверки; собранный DMG монтируется и содержит приложение, ссылку Applications и нужные ресурсы.

## Решение о публикации

Публиковать `v2.0.0-beta.1` как GitHub **prerelease**, если локальные и автоматические проверки прошли и ограничения перечислены в release notes. Не переключать `latest stable` с 1.0.39 на бету. Без испытания на реальной блокирующей сети нельзя объявлять, что Discord voice, UDP или любая стратегия гарантированно работают у пользователей. Отсутствие Developer ID/нотаризации явно указать; ad-hoc подпись не называть нотариальной проверкой Apple.

Для перехода к стабильной 2.0 обязательны результаты матрицы выше: установка/миграция на реальном Mac, восстановление сети после ошибок и sleep/wake, проверка arm64 и Intel, несколько сетей с блокировкой, отдельно голос Discord. Любые непроверенные комбинации должны быть исключены из заявленной поддержки или явно оговорены. Смена статуса выполняется отдельным релизом после исправления обнаруженных регрессий.

Фактические результаты сборки, проверок и публикации вносятся в [RELEASE-v2.0.0-beta.1.md](RELEASE-v2.0.0-beta.1.md). Этот план задаёт критерии, а не утверждает, что все аппаратные и полевые проверки уже выполнены.

## Статус 2.0.0-beta.1

Этапы 1–7 реализованы: исследование, новая модель привилегий, восстановление SOCKS, экспериментальный пакетный backend, диагностика, интерфейс и universal-упаковка. Результаты локальных проверок приведены в release notes; публикация проходит отдельный Xcode CI.

Для стабильной 2.0 остаются полевые и аппаратные проверки из списка выше: реальная миграция 1.x, привилегированные сетевые операции, sleep/wake, разные macOS/Intel и подтверждение работы нужных сервисов на блокирующих сетях. Эти пункты не подменяются unit-тестами.

## После 2.0

1. Собрать анонимизированные воспроизводимые отчёты по ISP и закрыть регрессии маршрутизации/восстановления до расширения списка движков.
2. Отдельно оценить SpoofDPI 1.5.4+: SOCKS/TUN, DNS, TCP/UDP, конфликты VPN и очистку состояния; сравнить эффективность с уже встроенными backend на одной сети.
3. Исследовать транспорт zapret2 для macOS: совместимость packet API, Lua runtime, стратегии, производительность, BPF/utun и управление привилегиями. Не принимать совместимость флагов nfqws1 как доказанную.
4. Developer ID, нотариальная проверка и подписанный механизм автообновлений; затем широкое распространение и более простой первый запуск.
